# Telegram-бот «Сон ребёнка»

Python 3.11+, aiogram 3, async SQLAlchemy, SQLite/PostgreSQL и APScheduler.

## Запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env  # Linux/macOS: cp .env.example .env
# укажите BOT_TOKEN в .env
python bot.py
```

Таблицы создаются автоматически. Для production рекомендуется запускать один экземпляр бота: задания APScheduler хранятся в памяти и восстанавливаются из БД при старте. Локально можно использовать SQLite; на Render укажите либо PostgreSQL, либо постоянный Render Disk через `DB_PATH`/абсолютный SQLite URL.

Относительный SQLite URL всегда разрешается относительно каталога проекта, поэтому запуск из другой рабочей папки не создаёт новую пустую базу. `init_db` только создаёт отсутствующие таблицы и безопасно добавляет отсутствующие колонки; существующие таблицы и записи не удаляются.

Для Docker с постоянным диском укажите `DB_PATH` и/или абсолютный путь смонтированного тома, например `DB_PATH=/data/sleep_tracker.db` и `DATABASE_URL=sqlite+aiosqlite:////data/sleep_tracker.db`. Без постоянного тома файловая система контейнера может быть заменена при redeploy.

## Постоянная база на Render

1. В Render Dashboard выберите **New → Postgres** и создайте базу в том же регионе, что и бот.
2. Откройте созданную базу и скопируйте **Internal Database URL**.
3. В сервисе бота откройте **Environment → Add Environment Variable**.
4. Создайте переменную `DATABASE_URL` и вставьте URL целиком без кавычек.
5. Выполните **Manual Deploy → Deploy latest commit**.

URL вида `postgres://...` или `postgresql://...` автоматически преобразуется для async-драйвера. Пароль базы нельзя добавлять в GitHub или `.env.example`.

Команды: `/start`, `/join CODE`, `/status`, `/day`, `/chart [7|14]`, `/ai_routine`, `/seed_data`, `/backup`, `/reset`, `/cancel`.

## Проверка проекта

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m tests.integration_check
```

Интеграционная проверка использует временную базу SQLite в памяти и не обращается к Telegram API.

## Хронология и AI-анализ

- `/day` или кнопка «📅 Хронология дня» показывает ленту сна, бодрствования и активностей. Доступны сегодня, вчера и выбор одной из последних 14 дат.
- После каждого пробуждения бот рассчитывает следующее окно сна. При наличии истории используется медиана фактических ВБ за 14 дней, иначе — возрастной ориентир.
- `/ai_routine` или кнопка «🧠 AI-Режим (Gemini)» отправляет Gemini обезличенную историю завершённых снов и активностей за последние 31 день и строит персональный паспорт режима.
- `/chart` и кнопка «📊 График снов (Неделя)» строят PNG-диаграмму за 7 или 14 дней. Ночной и дневной сон показаны разными цветами, а пунктиром отмечен возрастной ориентир.
- `/seed_data [FAMILY_CODE]` импортирует журнал `data/august_2026.txt` для текущего профиля администратора. Можно указать семейный код (например, `/seed_data G3XV5KPP`) для дополнительной проверки. Повторный запуск дедуплицирует записи по ребёнку и дате/времени.
- `/backup` отправляет администратору актуальный SQLite-файл в личный чат. Для PostgreSQL используется штатный backup провайдера.

Для AI-модуля добавьте ключ из Google AI Studio в `.env` или переменные окружения сервиса:

```env
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.7-flash
```

Проект использует поддерживаемый официальный пакет `google-genai`. Старый пакет `google-generativeai` архивирован Google и больше не поддерживается. Без `GEMINI_API_KEY` весь остальной функционал бота продолжает работать, а AI-команда показывает инструкцию по настройке.

Перед использованием AI-модуля учитывайте, что обезличенные интервалы сна и возраст в месяцах передаются в Google Gemini API. Имя, дата рождения, Telegram ID и семейный код не передаются. Ответ носит справочный характер и не заменяет консультацию педиатра.

## Семейный режим и приватность

- При подключении пользователь выбирает подпись: «Мама», «Папа», «Бабушка», «Няня» или своё имя.
- Администратор может открыть «👥 Семья» и заранее добавить участника по числовому Telegram ID.
- Первый `/start` предлагает создать новую семью или подключиться к существующей по коду.
- `/join CODE` работает из любого шага онбординга и не принимается за имя ребёнка.
- Администратор может выполнить полный сброс семьи, а участник — безопасно выйти из неё. Оба действия требуют подтверждения.
- База атомарно защищена от двух одновременно запущенных таймеров сна.
- У каждой записи хранится автор; системные уведомления рассылаются всей семье.
- В настройках администратор может включить тихий режим 22:00–07:00: напоминания в этот период пропускаются, ответы доставляются без звука.
- В настройках доступен UTF-8 CSV за 7 или 30 дней. Он открывается в Excel и формируется в памяти без временных файлов.

Часовой пояс задаётся через `BOT_TIMEZONE` при создании профиля. Даты хранятся в UTC.
